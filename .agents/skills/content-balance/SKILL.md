# 콘텐츠 보상·성장 설계

이 파일에서 세 단계 위가 프로젝트 루트다. [AGENTS.md](../../../AGENTS.md), [설계 방식](../../../설계_방식.md), [데이터 명세](../../../데이터_명세.md)를 읽고 현재 Codex 세션에서 작업한다. 사용자는 일반 문장으로 요청할 수 있다.

## 설계할 입력

- 기존 게임은 지정한 실행파일 또는 `원본/`에 놓인 설치본에서 시작한다. [클라이언트 분석 절차](../../../클라이언트_분석.md)에 따라 실행파일과 주변 리소스를 조사하고 `게임별/<게임>/AGENTS.md`가 있으면 함께 읽는다.
- 실행파일 조사·패키지 목록·문자열 수집과 실제 수치 테이블 추출을 구분한다. 추출한 테이블과 필드의 관계를 확인한 뒤 계산 입력을 만든다. 근거가 없으면 정량 분석을 완료했다고 주장하지 않는다.
- 비용·환급 등 일부 수치만 검증한 정적 분석은 `analyzed_partial`로 기록한다. 별도 계산기를 썼으면 `model_path: null`과 실제 `analysis_input_path`·`analysis_input_sha256`을 남긴다.
- 미확인 지급량·확률은 추가 추적 대상이다. 전체 패키지와 테이블 등록부에서 후보를 찾고 생성된 스키마 및 실제 호출 코드를 연결한다. 조사하지 않은 영역과 검색했지만 못 찾은 영역을 구분한다. 서버 응답 처리만 확인했으면 서버 알고리즘까지 알아냈다고 표현하지 않는다. 추가 조사는 기존 비용 결과를 보존한 별도 회차에 저장한다.
- 공개 보조 자료를 허용받았으면 공식 공시와 실측 원본의 버전·표본·선별 조건을 기록한다. 별도 확률 모델을 사용하면 계산이 포함한 재화와 시간 범위를 밝힌다.
- 대상 `콘텐츠/<게임>/<콘텐츠>/설정.json`, `모델.json`, 최신 `설계결과.json`과 연결된 계산·검토를 읽는다. 미등록이면 [new-content](../new-content/SKILL.md) 절차부터 이어서 수행한다.
- 사용자의 설계 목표를 코호트별 `targets`, 고정 조건을 `fixed_decisions`에 반영한다. 신규 설계의 제안 값은 가정으로 표시한다. 기존 게임의 현황 분석에는 임의 목표나 가상 수치를 넣어 실데이터로 취급하지 않는다.
- 새 회차 `결과/<YYYYMMDD_HHMMSS>_설계/`에 기준 입력을 `기준안.json`으로 복사한다. 미해결 변경안을 자동으로 확정안 취급하지 않는다.
- 변경안은 `변경안_1.json`부터 순서대로 저장한다. 값마다 변경 전후·단위·근거·이유를 기록하고, 원본 자료나 이전 회차를 덮어쓰지 않는다.

## 수치 계산과 수정

```bash
python3 도구/밸런스.py validate "<회차>/변경안_1.json"
python3 도구/밸런스.py simulate "<회차>/변경안_1.json" --out "<회차>/계산_1" --strict
```

- `--out`은 새 경로다. 종료 1은 입력/실행 오류, 종료 2는 결과는 생성됐으나 목표 미설정·미충족이다.
- `결과.json`의 전체 유저 p50/p90·미도달율, 플레이 시간, 재화 수급·부족량·미지불 소모를 읽고 병목을 찾는다. 목표에 없는 코호트도 검토한다.
- 수정이 필요하면 새 변경안과 계산을 남긴다. 목표를 낮춰 통과시키지 않으며, 계산하지 않은 도달일을 확정하지 않는다. 반복해도 목표가 충돌하면 계산된 대안과 어느 고정 조건이 충돌하는지 보고한다.

## 검토와 전달

- [설계 방식의 6관점](../../../설계_방식.md#관점-검토와-판정)으로 동일 입력을 자체 검토하고 `검토_n.json`에 남긴다. 기본 `review_mode`는 `self`다. 다중 에이전트가 요청된 경우에만 가능한 도구로 독립 검토하고 실제 수행 내역을 기록한다.
- 입력을 바꾸면 해시가 달라지므로 재계산하고 다시 검토한다. 이전 계산·승인을 새 입력에 재사용하지 않는다.
- 다음 명령으로 비교표와 HTML/CSV/JSON을 만든다. 두 입력의 days/samples/seed는 같아야 한다.

```bash
python3 도구/밸런스.py compare "<회차>/기준안.json" "<회차>/변경안_n.json" --out "<회차>/전후비교"
```

- `설계결과.json`은 설계 방식의 기록 계약에 맞춰 최종 입력·해시·계산/비교/검토 경로·상태·변경 이유·남은 가정을 남긴다. 최종 응답은 핵심 변경, 목표 충족/미도달, 병목, 보고서 링크로 정리한다.
- 실제 로그 검증도 요청받으면 [validate-balance](../validate-balance/SKILL.md) 절차를 이어서 수행한다. Word는 요청한 경우에만 만든다.
