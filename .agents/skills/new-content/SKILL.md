# 콘텐츠 등록

이 스킬은 `content-balance` 저장소 전용이다. 이 파일에서 세 단계 위가 프로젝트 루트다. [AGENTS.md](../../../AGENTS.md)와 [데이터 명세](../../../데이터_명세.md)를 확인한다. 사용자에게 명령을 다시 입력시키지 말고 요청한 등록을 수행한다.

## 기존 게임 분석

실행파일 하나만 받아도 [클라이언트 분석 절차](../../../클라이언트_분석.md)를 시작한다. 지정 경로가 없으면 `원본/`과 프로젝트 루트에 놓인 실행파일·모바일 패키지를 확인한다. 설치본을 식별해 인접 리소스를 찾고, `설정.json`에 원본 경로와 `analysis_mode: client`를 기록한다. 아직 대상 콘텐츠가 정해지지 않았으면 `클라이언트분석`으로 시작한다. 확인한 테이블에서 분석을 이어가고 리소스가 부족하면 필요한 파일명을 보고한다.

## 신규 콘텐츠 설계·가상 예제

1. 게임·콘텐츠·자료·목표를 대화에서 찾는다. 미지정 주기는 콘텐츠 성격에 맞춰 `daily`(일일), `raid`(주간), `event`(기간제)를 선택하고 가정으로 표시한다.
2. 아래 도구로 새 작업 폴더를 만든다. 이미 등록되어 있으면 해당 폴더를 읽어 이어간다. 사용자 문자열은 셸 인자로 안전하게 인용한다.

```bash
python3 도구/밸런스.py init --game "게임이름" --content "콘텐츠이름" --preset daily
```

3. 생성한 `설정.json`의 목적·자료 경로·확정 조건과 `모델.json`의 입력을 사용자 자료로 채운다. 원본 자료는 읽기 전용으로 참조하거나 `자료/`에 복사한다. WSL에서는 Windows 경로를 `/mnt/<드라이브>/...`로 해석한다.
4. 수치마다 원본 파일/행 또는 JSON pointer를 기록한다. 신규 설계의 제안 값은 가상 초안으로 남기고 `data_status`, `assumptions`에 명시한다. 기존 게임을 분석하는 요청에는 이 가상 초안 방식을 대신 적용하지 않는다. 지원하지 않는 메커니즘을 임의 치환하지 않는다.
5. `python3 도구/밸런스.py validate "콘텐츠/<게임>/<콘텐츠>/모델.json"`으로 검증한다.
6. 등록까지 요청했다면 생성 경로와 자료 공백을 보고한다. 설계도 요청했다면 [content-balance 스킬](../content-balance/SKILL.md)을 읽고 바로 설계·계산을 계속한다.
