# 콘텐츠 밸런스 (content-balance)

**Codex에서 게임 클라이언트의 보상·성장 데이터를 분석하고, 특정 콘텐츠의 밸런스를 설계하는 프로젝트**입니다. 기존 게임은 설치 폴더/APK 확보 → 형식 확인·패키지 추출 → 테이블 연결 → 계산 → 검토 순서로 진행합니다. 신규 콘텐츠 설계는 별도 제안 모델로 시작합니다.

예: 성장 던전의 일일 보상을 얼마나 줄지, 주간 레이드 성장 재료로 목표 단계까지 몇 주가 걸릴지, 14일 이벤트가 끝나기 전에 무과금 유저가 목표를 달성할 수 있을지.

## 바로 시작

Codex 앱에서 `C:\Sans\content-balance`를 프로젝트로 열고, 일반 문장으로 요청하세요.

```text
명조의 보상·성장 밸런스를 클라이언트 데이터 기준으로 분석해줘.
설치 폴더는 D:\Wuthering Waves\Wuthering Waves Game 이야.
실제 보상표와 성장 비용을 추출하고, 확인한 수치와 못 읽은 항목을 구분해줘.
```

Codex CLI에서는 작업 폴더를 지정해 시작할 수 있습니다.

```powershell
codex -C C:\Sans\content-balance
```

WSL에서는 `codex -C /mnt/c/Sans/content-balance`를 사용합니다. 프로젝트 스킬을 직접 지정하려면 다음처럼 입력할 수 있습니다.

```text
$new-content 내게임의 성장던전을 일일 콘텐츠로 등록해줘
$content-balance 성장던전의 무과금 목표 도달 기간을 14~21일로 설계해줘
$validate-balance 성장던전 모델을 검증하고 제공한 집계 로그와 대조해줘
```

프로젝트 지침은 [AGENTS.md](AGENTS.md), 스킬은 `.agents/skills/`에 있습니다. Codex의 프로젝트 지침·로컬 스킬 형식에 맞췄습니다. [공식 AGENTS.md 안내](https://learn.chatgpt.com/docs/agent-configuration/agents-md), [공식 로컬 스킬 안내](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills).

신규 콘텐츠 설계·가상 예제에는 `daily`(일일 던전), `raid`(주간 레이드), `event`(14일 이벤트) 프리셋을 사용합니다. **프리셋·예제 수치는 모두 가상이며 기존 게임의 원본 분석을 대신하지 않습니다.**

기존 게임의 원본 경로가 없으면 먼저 설치 폴더/APK 경로를 확인합니다. Python 계산기는 정리된 모델을 계산하는 도구이며 자동 역컴파일 도구가 아닙니다. 패키지 형식에 맞는 추출기를 실제 적용해야 하고, 패키지 내부를 못 읽었으면 추출 완료로 표시하지 않습니다. 자세한 절차와 현재 도구 범위는 [클라이언트_분석.md](클라이언트_분석.md)에 있습니다.

**명조 Windows 설치본용 PAK v12 추출·DB 해석·정적 비용 분석 도구가 포함되어 있습니다.** 실제 실행 절차와 의존성은 [명조_분석_안내.md](명조_분석_안내.md)를 확인하세요. `콘텐츠/명조/클라이언트분석/`에는 로컬 설치본을 읽어 만든 분석 결과가 있습니다. 가상 예제와 별도입니다.

최신 문서는 [명조 문서 모음](문서/명조/index.html)에 목적별로 정리했습니다. [기획서](문서/명조/기획서/index.html)는 설계 목적·규칙·파라미터, [분석서](문서/명조/분석서/index.html)는 수학·통계·현황 근거, [제안서](문서/명조/제안서/index.html)는 변경안·대안 비교·선택 이유를 담습니다. 각 유형 20개와 통합 문서, 209개 개별 근거표, 392개 이벤트 등록부가 있습니다. 프로젝트 루트의 [index.html](index.html)에서도 열 수 있습니다.

한 던전의 재화 흐름과 개선 이유부터 보려면 [중부 평원 무음구역 단일 보고서](개별보고서/명조_중부평원_무음구역/중부평원_무음구역_재화분석과_개선안.html)를 여세요. 별도 폴더의 한 HTML에 실제 아이콘, 수급·소비 분석, 튜너 24개안과 검증 계획을 담았습니다. 문서 모음의 기획서·제안서는 문제와 변경 이유를 먼저 설명하고, 수식·설정 ID는 상세 참고로 분리합니다.

신규 콘텐츠 제안 형식은 [잔향 정제실 인터랙티브 예시](문서/명조/제안서/신규던전_잔향정제실_인터랙티브.html)에서 볼 수 있습니다. 가상 던전의 기본 콘셉트와 제공 재화를 읽고 공통 비용·지급 배율로 세 난이도를 동시에 조정합니다. 기존 파밍 대체, 참여율, 난이도 비중, 기타 수입과 소비를 반영해 7일 재화 공급·부족량·대상 이용자 총량이 그래프와 표에 함께 표시됩니다. `python3 도구/신규던전_제안예시.py`로 예시를 재생성할 수 있습니다.


재화·보상 473종, 콘텐츠 유형 20개, 개별 가이드 209개에 설치본의 실제 아이콘을 연결했습니다. 이름·등급·수량을 함께 표시하며, [재화·콘텐츠 사전](문서/명조/재화_콘텐츠_사전.html)에서 이름과 ID로 검색할 수 있습니다. 이미지가 포함되어 오프라인으로 열 수 있습니다. 「꿈의 칩」 1종은 원본 이미지 연결 미확인으로 남겼습니다. 아이콘 추가 전 문서는 `문서/명조_보관_20261118_아이콘이전/`에 보존했습니다.

**화면에 ‘예시게임 / 성장던전’이라고 표시된 자료는 계산기 검증용 가상 예제이며 명조가 아닙니다.** 기존 게임을 분석한 명조 문서는 실제 자료를 사용합니다. 별도의 잔향 정제실 신규 제안은 첫 화면에 가상 설계임을 표시합니다. 공식 부옵션 확률과 공개 실측 7,614건으로 조건부 재화 파밍을 계산했습니다. 실측은 과거 버전이며 행동력 환산일에 후보 획득·전투 시간은 포함되지 않습니다.

## Python만으로 사용

아래 모델 계산 CLI는 Python 3.10 이상이면 됩니다. 추가 패키지나 API 키가 필요 없습니다. 명조의 암호화 패키지 추출에는 별도 의존성이 있습니다. Windows에서는 아래 `python3`를 `py -3` 또는 `python`으로 바꿀 수 있습니다.

```bash
cd /mnt/c/Sans/content-balance

# 새 콘텐츠 등록 (이미 있는 폴더는 덮어쓰지 않음)
python3 도구/밸런스.py init --game "내게임" --content "성장던전" --preset daily

# 해당 폴더의 설정.json과 모델.json을 수정한 뒤
python3 도구/밸런스.py validate "콘텐츠/내게임/성장던전/모델.json"
python3 도구/밸런스.py simulate "콘텐츠/내게임/성장던전/모델.json" --strict

# 제공 예제 계산: --out을 생략하면 결과 아래에 새 시간별 폴더 생성
python3 도구/밸런스.py simulate "예제/성장던전/모델.json"
python3 도구/밸런스.py compare "예제/성장던전/모델.json" "예제/성장던전/개선안.json"
python3 도구/밸런스.py logs "예제/성장던전/모델.json" "예제/성장던전/가상_로그.csv"

# 도구 자체 검증
python3 -m unittest discover -s tests -v

```

`--out <새 폴더>`로 저장 위치를 지정할 수 있습니다. 기존 회차는 덮어쓰지 않습니다. `simulate --strict`의 종료 코드 2는 **목표 미설정 또는 미충족이며 계산 결과는 저장된 상태**입니다. 입력/파일 오류는 1, 정상 실행은 0입니다. Python 명령은 AI 에이전트를 호출하지 않습니다.

## 결과 읽기

`리포트.html`을 브라우저로 열면 유저 유형별 도달 기간, 누적 도달률 곡선, 재화 수급, 목표 판정, 가정을 볼 수 있습니다. 서버·네트워크가 필요 없습니다.

| 파일 | 용도 |
| --- | --- |
| `입력_스냅샷.json`, `결과.json` | 원본 입력·시드·표본 수·입력 SHA-256을 포함한 재현 기록 |
| `보상표.csv` | 반복/최초 보상, 확률, 그룹, 난이도 |
| `성장표.csv` | 단계별 비용·누적 비용·전투력 |
| `보상_기대값.csv` | 난이도별 1클리어·1시도·1분 기대값; 최초 보상 제외, 코호트 보정 전 |
| `코호트_요약.csv`, `일별_추이.csv` | 유형별 목표 기간·도달률·단계·일별 재화 부족량 |
| `재화_수급.csv` | 유저 1명당 기간 누적 공급·소모·잔액 보존식 |
| `비교.html`, `전후_비교.csv` | compare 실행 시 생성; 하위 폴더에 두 안의 전체 결과 |
| `로그_검증.html`, `로그_대조.csv`, `로그_검증.json` | logs 실행 시 생성; 관측 집계와 모의 계산의 차이 |
| `설계결과.json`, `검토_n.json` | Codex가 설계 작업 시 작성; 최종 입력·해시·변경 이유·실제 검토 방식·남은 가정 |

`p90=null`은 90%가 관측 기간 안에 도달하지 않았다는 뜻이 아니라, **기간 내 도달률이 90%에 못 미쳐 90번째 백분위의 도달일을 알 수 없다**는 뜻입니다. 도달한 사람들만의 중앙값은 `reached_only_p50`로 따로 남기며 전체 중앙값으로 사용하지 않습니다.

보고서의 `pass`는 `targets`에 명시한 코호트만의 입력 목표를 충족했다는 뜻입니다. 목표에 없는 라이트 유저의 미도달은 경고로 남습니다. 서비스 적합성·매출 증가·실측 예측 정확도를 보증하는 상태가 아닙니다.

## 자료 준비

기존 게임은 PC 설치 폴더 또는 APK와 추가 리소스를 원본으로 등록합니다. `콘텐츠/<게임>/<콘텐츠>/설정.json`에 `analysis_mode: client`, `source_inputs`, 분석 목적·확정 조건을 적습니다. 실제 테이블이 확인된 뒤 `모델.json`을 작성합니다. `game-atlas`에 추출본이 있으면 원본과 추출 방식·버전을 확인하고 필요한 경로를 `materials`에 연결합니다. 서버 전용 테이블·읽지 못한 패키지의 수치를 지어내지 않습니다.

설정의 `materials` 항목 예:

```json
{"path":"/mnt/c/Sans/game-atlas/게임/내게임/추출/던전보상.csv","description":"현재 성장던전 보상표, 읽기 전용"}
```

모델 필드·확률 그룹·리셋·로그 CSV 계약은 [데이터_명세.md](데이터_명세.md), 설계 진행 방식은 [설계_방식.md](설계_방식.md)를 참조하세요.

## 적용 범위

- 성장 비용을 내면 **확정 성장**합니다. 강화 실패·파괴·천장·중복 아이템·세트 효과는 현재 엔진 범위 밖입니다.
- 전투력은 결과 표시용입니다. 클리어율은 단계별 입력값이며 전투력에서 자동 산출하지 않습니다.
- 참여일은 유저별·날짜별 독립 추첨입니다. 정확히 주 4일 접속하거나 실제 이탈/복귀하는 행동 모델이 아닙니다.
- 외부 일일 공급·소모·예약 구매는 미접속일에도 처리합니다. 잔액 한도·입장권 소멸·이월 상한은 없습니다. 참여 횟수만 리셋됩니다.
- 재화가 충분하면 즉시 성장하고, 이용 가능한 최고 난이도를 우선하며, 목표 도달 후에도 계속 플레이합니다. 선택 최적화나 성장 중단 전략을 계산하지 않습니다.
- 재화가 없으면 기타 소모는 가능한 만큼만 납부하고 나머지는 `unpaid_sink`로 남깁니다. 부채를 다음 날로 넘기지 않습니다.
- 확률 계산에는 표본 오차가 있습니다. `reach_rate_mc_se`는 모의 표본의 오차 지표이며 실측 예측 신뢰구간이 아닙니다.
